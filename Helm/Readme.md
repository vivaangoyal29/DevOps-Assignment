## 3. Upgrading and Scaling Deployments
The `vivaan-app` deployment underwent multiple revisions. It was successfully upgraded to Revision 2. Following this, the application was scaled horizontally by upgrading the release with the `--set replicaCount=3` flag, advancing the release to Revision 3. 

![Helm Upgrade Revision 2](Screenshot%202026-10-09%20000345.png)
![Helm Upgrade Scale Replicas](Screenshot%202026-10-09%20000436.png)

The successful scaling operation was verified by retrieving all cluster resources, confirming that the Desired, Current, and Ready replica counts for `vivaan-app-app` were all successfully updated to 3.

![Kubectl Get All Resources](Screenshot%202026-10-09%20000500.png)

## 4. Handling Deployment Failures and Rollbacks
To demonstrate Helm's rollback capabilities, an intentional configuration error was introduced. The `notes-dev` release was upgraded using a non-existent image tag (`--set image.tag=broken-tag-does-not-exist`). As expected, this resulted in an `ErrImagePull` status for the newly spun-up pods.

![Helm Upgrade Error](Screenshot%202026-10-09%20001141.png)

To resolve the broken deployment, a `helm rollback notes-dev 2` command was executed. This successfully restored the application to its previous stable state, terminating the broken pods and ensuring the healthy pods returned to a `Running` status.

![Helm Rollback](Screenshot%202026-10-09%20001215.png)

## 5. Final State Verification
The overall state of the cluster was validated at the end of the assignment. The `helm list` command confirmed that `demo-chart` (Revision 1) and `vivaan-app` (Revision 3) were actively deployed and functioning. A final check of the pods confirmed that all services, including `notes-dev` and the scaled `vivaan-app` replicas, were running smoothly.
